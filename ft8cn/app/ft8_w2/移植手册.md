# ft8_w2 移植手册

本手册说明如何把 `ft8_w2`（`ft8_w` 的 FT8 C 解码核心）接入 FT8CN，新增一个
**独立解码挡位 `ft8_w2`**，与原有 `快速 / 深度 / wsjtx普通多核` 并存。

- 交付版本：`0.1.0`
- 原生库：`libft8.so`（`System.loadLibrary("ft8")`）
- ABI：`arm64-v8a`、`x86_64`
- 编译目标：`android-23`（与 FT8CN `minSdk 23` 一致）
- 解码档位：`precise` 单档（不做信号消除）

---

```text
ft8_w2/
├─ README.md                         本包简介
├─ VERSION.txt                       版本与构建信息
├─ LICENSE-NOTICE.md                 第三方许可（ft8_lib, MIT）
├─ 移植手册.md                        本文件
├─ java/
│  └─ com/
│     ├─ ft8/nativecore/Ft8Native.java          JNI 绑定（包名不可改）
│     └─ bg7yoz/ft8cn/ft8w/Ft8WDecoder.java     FT8CN 适配层（precise 档）
├─ jniLibs/
│  ├─ arm64-v8a/libft8.so             111 KB，14 个 JNI 导出
│  └─ x86_64/libft8.so                124 KB，14 个 JNI 导出
├─ jni/ft8_jni.cpp                    JNI 源码（重新编译时使用）
└─ scripts/build.ps1                  重新构建 libft8.so
```

> `libft8.so` 与 FT8CN 原有的 `libft8cn.so`、`libwsjtx_Android.so` 互不冲突，
> 可以同时打包进同一个 APK。

## 3. 复制文件

在 `ft8cn/app/` 下执行（假设本包位于 `ft8cn/app/ft8_w2/`）：

```powershell
$app = "ft8cn\app"
$pkg = "$app\ft8_w2"

# 1) 原生库
New-Item -ItemType Directory -Force -Path "$app\libs\arm64-v8a","$app\libs\x86_64" | Out-Null
Copy-Item "$pkg\jniLibs\arm64-v8a\libft8.so" "$app\libs\arm64-v8a\libft8.so" -Force
Copy-Item "$pkg\jniLibs\x86_64\libft8.so"    "$app\libs\x86_64\libft8.so"    -Force

# 2) Java 类（包路径必须一致）
New-Item -ItemType Directory -Force -Path `
    "$app\src\main\java\com\ft8\nativecore", `
    "$app\src\main\java\com\bg7yoz\ft8cn\ft8w" | Out-Null
Copy-Item "$pkg\java\com\ft8\nativecore\Ft8Native.java" `
    "$app\src\main\java\com\ft8\nativecore\Ft8Native.java" -Force
Copy-Item "$pkg\java\com\bg7yoz\ft8cn\ft8w\Ft8WDecoder.java" `
    "$app\src\main\java\com\bg7yoz\ft8cn\ft8w\Ft8WDecoder.java" -Force
```

目录结果：

```text
ft8cn/app/libs/arm64-v8a/libft8.so
ft8cn/app/libs/x86_64/libft8.so
ft8cn/app/src/main/java/com/ft8/nativecore/Ft8Native.java
ft8cn/app/src/main/java/com/bg7yoz/ft8cn/ft8w/Ft8WDecoder.java
```

> **不要修改** `Ft8Native` 的包名与方法名。JNI 符号是
> `Java_com_ft8_nativecore_Ft8Native_*`，改名会直接 `UnsatisfiedLinkError`。

## 4. 代码改动

共 5 处：挡位常量、解码分支、配置界面、布局/字符串、持久化校验。
下面给出可直接照抄的片段。

### 4.1 `GeneralVariables.java` —— 新增挡位常量

在原有 6 个挡位常量后追加：

```java
public static final int DECODE_MODE_FT8W = 6;//ft8_w2（libft8.so，precise档）
```

在 `isWsjtxDeepMode()` 之后新增判断：

```java
/**
 * 当前挡位是不是 ft8_w（libft8.so）解码。
 *
 * @return true 表示使用 ft8_w2 档
 */
public static boolean isFt8wDecodeMode() {
    return decodeMode == DECODE_MODE_FT8W;
}
```

在 `getDecodeModeName()` 的 `switch` 中新增分支（放在 `default` 之前）：

```java
case DECODE_MODE_FT8W:
    return getStringFromResource(R.string.ft8w_mode);
```

### 4.2 `FT8SignalListener.java` —— 解码分支

**(1) 导入：**

```java
import com.bg7yoz.ft8cn.ft8w.Ft8WDecoder;
```

**(2) 可用性标志**（与 `wsjtxAvailable` 并列）：

```java
//ft8_w（libft8.so）是否可用。缺少对应ABI的so时回退
private volatile boolean ft8wAvailable = true;
```

**(3) `decodeFt8()` 内，在 `int mode = ...; ArrayList<Ft8Message> decoded = null;`
之后插入：**

```java
//ft8_w挡位：使用libft8.so（precise档）解码
if (GeneralVariables.isFt8wDecodeMode() && ft8wAvailable) {
    decoded = decodeByFt8w(utc, voiceData);
    if (decoded == null) {
        //当前设备ABI没有对应so，后续直接回退
        ft8wAvailable = false;
    } else {
        publishFt8wMessages(utc, decoded, time);
    }
}
```

保持后面原有逻辑不变。因为 ft8_w 成功后 `decoded != null`，不会落入
`decodeByLegacy()`；失败时 `decoded == null`，会自动走原来的快速解码，
保证“任何设备都能出声”。

**(4) 新增解码与回调方法**（可放在 `decodeByWsjtx()` 之后）：

```java
ArrayList<Ft8Message> decodeByFt8w(long utc, float[] voiceData) {
    try {
        Ft8WDecoder.Row[] rows = Ft8WDecoder.decodeOnce(
                voiceData, FT8Common.SAMPLE_RATE);
        return toFt8Messages(rows, utc);
    } catch (Throwable e) {
        //UnsatisfiedLinkError、ExceptionInInitializerError等都从这里回退
        Log.e(TAG, "ft8_w解码不可用，回退到原解码器：" + e.getMessage(), e);
        return null;
    }
}

private void publishFt8wMessages(long utc, ArrayList<Ft8Message> msgs,
                                 long startTime) {
    timeSec = System.currentTimeMillis() - startTime;
    decodeTimeSec.postValue(timeSec);
    safeAfterDecode(utc, msgs, msgs, false);
    Log.d(TAG, String.format("ft8_w解码完成，共%d条", msgs.size()));
}
```

**(5) 结果转换**（新增 `Row` 版本，避免与 wsjtx 的 `Row` 重载混淆）：

```java
private ArrayList<Ft8Message> toFt8Messages(Ft8WDecoder.Row[] rows, long utc) {
    ArrayList<Ft8Message> out = new ArrayList<>();
    if (rows == null) return out;

    for (Ft8WDecoder.Row row : rows) {
        Ft8Message msg = toFt8Message(row, utc);
        //与原来的解码器保持一致：相同报文只保留一条
        if (msg != null && !checkMessageSame(out, msg)) out.add(msg);
    }
    return out;
}

private Ft8Message toFt8Message(Ft8WDecoder.Row row, long utc) {
    if (row == null) return null;

    String text = row.text == null ? "" : row.text.trim();
    if (text.isEmpty()) return null;

    Ft8Message msg = new Ft8Message(FT8Common.FT8_MODE);
    msg.utcTime = utc;
    msg.isValid = true;
    msg.snr = Math.round(row.snr);
    msg.time_sec = row.dt;
    msg.freq_hz = row.freq;
    msg.band = GeneralVariables.band;
    msg.signalFormat = FT8Common.FT8_MODE;
    msg.isWeakSignal = false;
    //空字符串而不是 null：下游会直接使用
    msg.maidenGrid = "";

    if (row.structured) {
        msg.i3 = row.i3;
        msg.n3 = row.n3;
        msg.callsignTo = row.callTo == null ? "" : row.callTo;
        msg.callsignFrom = row.callDe == null ? "" : row.callDe;
        msg.extraInfo = row.extra == null ? "" : row.extra;
        msg.maidenGrid = row.grid == null ? "" : row.grid;
        //从附加信息里补信号报告（“-12”“R-05”等）
        msg.report = parseReport(row.extra);
    } else {
        // 兼容没有结构化字段的旧版 so
        parseWsjtxText(msg, text);
        parseWsjtxExtra(msg);
    }
    msg.displayText = text;
    return msg;
}

private int parseReport(String extra) {
    if (extra == null) return -100;
    String s = extra.trim().toUpperCase();
    if (s.matches("R?[+-]\\d{1,2}")) {
        try {
            return Integer.parseInt(s.startsWith("R") ? s.substring(1) : s);
        } catch (NumberFormatException ignored) {
        }
    }
    return -100;
}
```

### 重新编译 `libft8.so`

只有在修改了 C 核心或 JNI 桥时才需要。依赖 NDK + CMake + Ninja：

```powershell
# 默认源码目录 D:\Desktop\ft8_w\native
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1

# 源码在别处
```

## 6. 运行验证

1. 打开 FT8CN → 设置 → 解码模式，应看到 4 个选项：
   `快速解码 / 深度解码 / wsjtx普通多核 / ft8_w2`。
2. 选中 `ft8_w2`，返回主界面，收到一个时隙后观察日志：

```text
adb logcat -s FT8SignalListener
```

预期出现：

```text
ft8_w解码完成，共N条
```

3. 界面上的报文、SNR、DT、频率应正常显示；呼号/网格/报告能直接用于通联。
4. 切回 `wsjtx普通多核`，功能应与改动前完全一致。

### 量化基准（宿主 clang，`--repeat 6`）

| 指标 | 数值 |
| --- | --- |
| 测试集 | 69 个 wav / 1298 条 |
| 命中 | 953 |
| 召回 | 73.4% |
| 平均耗时 | 14.2 ms |
| P95 耗时 | 15.6 ms |

手机端耗时通常是宿主的 3~8 倍，仍远低于单时隙 1000 ms 的上限。

## 7. 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `UnsatisfiedLinkError: dlopen failed: library "libft8.so" not found` | 当前 ABI 没有对应 so | 确认 `app/libs/<abi>/libft8.so` 存在；或让该挡位自动回退（本接入已实现） |
| `UnsatisfiedLinkError: Java_com_ft8_nativecore_Ft8Native_xxx` | 改了 `Ft8Native` 包名/方法名 | 恢复包名 `com.ft8.nativecore` 与方法签名 |
| 界面没有“ft8_w2” | 布局/字符串没加，或 `ConfigFragment` 没引用 | 检查 4.3、4.4 |
| 选了挡位、重启后变回 wsjtx | 漏改 `DatabaseOpr` 白名单 | 按 4.5 补 `DECODE_MODE_FT8W` |
| 解码结果为空但 wsjtx 正常 | 音频不满足 12 kHz 单声道 float | 确认传入 `FT8Common.SAMPLE_RATE`，且音频已在 -1.0~1.0 |
| 解码耗时异常高 | 误开了 `num_threads`/`subtract` | 保持 `Ft8WDecoder.preciseConfig()` 默认值 |
| APK 体积变大 | 多打包了两个 ABI 的 so | 正常，合计约 235 KB |

日志关键字：

```text
ft8_w解码不可用，回退到原解码器：...
ft8_w解码完成，共N条
```

## 8. 调参

所有解码参数集中在 `Ft8WDecoder.preciseConfig(int sampleRate)`，返回 17 元素
`float[]`，下标定义见 `jni/ft8_jni.cpp` 的 `DC_` 枚举：

| 下标 | 字段 | precise 取值 | 说明 |
| --- | --- | --- | --- |
| 0 | fmin | 200 | 起始音频频率 |
| 1 | fmax | 3000 | 结束音频频率 |
| 2 | sample_rate | 12000 | 采样率 |
| 3 | time_osr | 2 | 时间过采样 |
| 4 | freq_osr | 2 | 频率过采样 |
| 5 | max_candidates | 100 | 最大候选数 |
| 6 | min_sync_score | 10 | 最小同步分 |
| 7 | ldpc_iterations | 20 | LDPC 迭代次数 |
| 8 | decode_depth | 0 | 多遍消除层数（0=关闭） |
| 9 | ap_mode | 0 | AP 辅助解码 |
| 10 | enable_subtract | 0 | 信号消除开关 |
| 11 | num_threads | 1 | 线程数 |
| 12 | return_duplicates | 0 | 是否返回重复 |
| 13 | osd_depth | 3 | OSD 深度 |
| 14 | enable_llr_refine | 0 | LLR 重解（默认关闭） |
| 15 | snr_mode | 2 | SNR 估计模式（2=抽取式快速） |
| 16 | subtract_max_signals | 0 | 每遍最多消除信号数 |

> 调大 `decode_depth` / 打开 `enable_subtract` 可以提高弱信号召回，
> 但耗时成倍增加；默认的 precise 档是在召回与耗时之间取的平衡点。

## 9. 与原有挡位的关系

| 挡位 | 实现 | 说明 |
| --- | --- | --- |
| 快速解码 (0) | 原 FT8CN 解码器 | 一次解码 |
| 深度解码 (1) | 原 FT8CN 解码器 | 多轮迭代 |
| wsjtx普通多核 (4) | `libwsjtx_Android.so` | 频谱分段并行 |
| **ft8_w2 (6)** | **`libft8.so`** | **precise 单档，独立实现** |

- 三个原生库可同时存在，互不干扰。
- `ft8_w` 失败（ABI 不支持/加载失败）时自动回退到原快速解码。
- 不修改 wsjtx 与 legacy 的任何参数，原有行为保持不变。
