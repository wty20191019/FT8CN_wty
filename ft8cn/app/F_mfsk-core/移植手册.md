# FT8CN 接入 mfsk-core（FT8 解码）移植手册

## 1. 这个目录是什么

本目录提供一套**只做 FT8 解码**的 Android 原生库和 Java 适配层：

```
F_mfsk-core/
├── jniLibs/
│   ├── arm64-v8a/libwsjtx_Android.so     ← 真机用
│   └── x86_64/libwsjtx_Android.so        ← 模拟器用
├── java/com/bg7yoz/ft8cn/wsjtx/
│   └── WsjtxDecoder.java                  ← Java 调用入口
├── jni/wsjtx_jni.c                        ← 很薄的 JNI 封装
├── include/mfsk.h                         ← mfsk-ffi 的 C ABI 头文件
├── scripts/build.ps1                      ← 重新构建脚本
└── 移植手册.md
```

核心算法来自 **mfsk-core**（WSJT-X 算法的 Rust 实现，GPL-3.0-or-later）。
它不是把 WSJT-X 的 Fortran 直接搬过来，而是按 WSJT-X 的 FT8/FT4 流程重写的
Rust 库；解码能力、LDPC/BP/OSD、同步和减法都在库内部完成。

> **重要：不要替换 FT8CN 的 `libft8cn.so`。**
> 那个库里还有频谱、重采样、GPL 编码、`pack77`、GFSK 合成等 FT8CN 必需功能。
> 本目录的 `libwsjtx_Android.so` 是**第二个库**，只负责 FT8 解码。

### 第 3 步：改 `FT8SignalListener.java`

文件：

```
ft8cn/app/src/main/java/com/bg7yoz/ft8cn/ft8listener/FT8SignalListener.java
```

在文件顶部加 import：

```java
import com.bg7yoz.ft8cn.wsjtx.WsjtxDecoder;
```

把原来的 `decodeFt8(...)` 方法整体替换为下面这版。
它保留原来的 `beforeListen/afterDecode` 回调、耗时统计和深解码逻辑，
但不再调用 `InitDecoder/DecoderMonitorPressFloat/DecoderFt8FindSync/...`。

```java
public void decodeFt8(long utc, float[] voiceData) {
    new Thread(new Runnable() {
        @Override
        public void run() {
            long time = System.currentTimeMillis();
            if (onFt8Listen != null) {
                onFt8Listen.beforeListen(utc);
            }

            ArrayList<Ft8Message> allMsg = new ArrayList<>();
            try {
                // 普通解码
                WsjtxDecoder.Row[] rows = WsjtxDecoder.decodeOnce(
                        voiceData, FT8Common.SAMPLE_RATE, false);
                ArrayList<Ft8Message> msgs = toFt8Messages(rows, utc, false);
                addMsgToList(allMsg, msgs);
                timeSec = System.currentTimeMillis() - time;
                decodeTimeSec.postValue(timeSec);
                if (onFt8Listen != null) {
                    onFt8Listen.afterDecode(utc, averageOffset(allMsg),
                            UtcTimer.sequential(utc), msgs, false);
                }

                // 深度解码：BP_ALL_OSD + DEEP 门限
                if (GeneralVariables.deepDecodeMode) {
                    rows = WsjtxDecoder.decodeOnce(
                            voiceData, FT8Common.SAMPLE_RATE, true);
                    msgs = toFt8Messages(rows, utc, true);
                    addMsgToList(allMsg, msgs);
                    timeSec = System.currentTimeMillis() - time;
                    decodeTimeSec.postValue(timeSec);
                    if (onFt8Listen != null) {
                        onFt8Listen.afterDecode(utc, averageOffset(allMsg),
                                UtcTimer.sequential(utc), msgs, true);
                    }
                }
            } catch (Exception e) {
                Log.e(TAG, "decodeFt8: " + e.getMessage(), e);
            }

            Log.d(TAG, String.format("解码耗时:%d毫秒",
                    System.currentTimeMillis() - time));
        }
    }).start();
}
```

> `WsjtxDecoder.decodeOnce(...)` 每次 open/decode/close，逻辑最简单。
> 一个时隙 15 秒，这点开销可以忽略。想省掉反复打开的开销，见第 3.1 节。

### 第 4 步：把解码行转成 `Ft8Message`

在 `FT8SignalListener` 里加下面这些方法（放在 `averageOffset` 附近即可）：

```java
private ArrayList<Ft8Message> toFt8Messages(WsjtxDecoder.Row[] rows,
                                             long utc,
                                             boolean isDeep) {
    ArrayList<Ft8Message> out = new ArrayList<>();
    if (rows == null) return out;

    for (WsjtxDecoder.Row row : rows) {
        Ft8Message msg = toFt8Message(row, utc, isDeep);
        if (msg != null) out.add(msg);
    }
    return out;
}

private Ft8Message toFt8Message(WsjtxDecoder.Row row,
                                long utc,
                                boolean isDeep) {
    if (row == null) return null;

    String text = row.text == null ? "" : row.text.trim();
    if (text.isEmpty()) return null;

    Ft8Message msg = new Ft8Message(FT8Common.FT8_MODE);
    msg.utcTime = utc;
    msg.isValid = true;
    msg.snr = Math.round(row.snr);
    msg.time_sec = row.dt;
    msg.freq_hz = row.freq;
    msg.band = GeneralVariables.band;
    msg.signalFormat = FT8Common.FT8_MODE;
    msg.isWeakSignal = isDeep;

    String[] t = text.split("\\s+");
    if (t.length >= 2
            && (t[0].equals("CQ") || t[0].equals("DE")
                || t[0].equals("QRZ") || looksLikeCall(t[0]))
            && looksLikeCall(t[1])) {
        // CQ CALL [extra] / CALL1 CALL2 [extra]
        msg.callsignTo = t[0];
        msg.callsignFrom = t[1];
        msg.extraInfo = joinFrom(t, 2);
        msg.i3 = (isNonStandard(t[0]) || isNonStandard(t[1])) ? 4 : 1;
        msg.n3 = 0;
    } else {
        // 自由文本：i3=0, n3=0
        msg.callsignTo = "";
        msg.callsignFrom = "";
        msg.extraInfo = text;
        msg.i3 = 0;
        msg.n3 = 0;
    }

    if (msg.extraInfo == null) msg.extraInfo = "";
    if (msg.callsignTo == null) msg.callsignTo = "";
    if (msg.callsignFrom == null) msg.callsignFrom = "";

    // 从扩展字段里提取报告和网格
    String[] extra = msg.extraInfo.split("\\s+");
    for (String token : extra) {
        String s = token.toUpperCase();
        if ((s.matches("R?[+-]?\\d{1,2}")) && msg.report == -100) {
            try {
                msg.report = Integer.parseInt(s.startsWith("R") ? s.substring(1) : s);
            } catch (NumberFormatException ignored) {
            }
        } else if (s.matches("[A-R]{2}[0-9]{2}([A-X]{2})?")) {
            msg.maidenGrid = s;
        }
    }

    return msg;
}

private boolean looksLikeCall(String token) {
    if (token == null || token.isEmpty() || token.length() > 13) return false;
    boolean hasLetter = false;
    for (int i = 0; i < token.length(); i++) {
        char c = Character.toUpperCase(token.charAt(i));
        if (c >= 'A' && c <= 'Z') {
            hasLetter = true;
        } else if (!(c >= '0' && c <= '9')
                && c != '/' && c != '<' && c != '>') {
            return false;
        }
    }
    return hasLetter;
}

private boolean isNonStandard(String call) {
    return call.indexOf('/') >= 0
            || call.indexOf('<') >= 0
            || call.indexOf('>') >= 0;
}

private String joinFrom(String[] tokens, int from) {
    if (tokens.length <= from) return "";
    StringBuilder sb = new StringBuilder();
    for (int i = from; i < tokens.length; i++) {
        if (sb.length() > 0) sb.append(' ');
        sb.append(tokens[i]);
    }
    return sb.toString();
}
```

## 3.1 可选：复用同一个解码器实例

`decodeOnce` 每次都会新建 session。FT8 的呼号哈希表、已知信号缓存
不会跨时隙保留。想保留这些状态，可以改成实例：

```java
// 字段
private WsjtxDecoder wsjtxDecoder;

// 构造函数里
wsjtxDecoder = new WsjtxDecoder(WsjtxDecoder.MODE_FT8);

// 解码时
WsjtxDecoder.Row[] rows = wsjtxDecoder.decode(
        voiceData, FT8Common.SAMPLE_RATE, false);

// 界面销毁时（例如 MainViewModel.onCleared 或 Activity.onDestroy）
wsjtxDecoder.close();
```

一个实例只在一个线程里调用 `decode()`。FT8CN 当前是在后台线程解码，
符合这个约束。

## 4. JNI API 参考

Java 类：`com.bg7yoz.ft8cn.wsjtx.WsjtxDecoder`

| Java 方法 | 说明 |
|---|---|
| `new WsjtxDecoder(int mode)` | mode: `MODE_FT8 = 0`，`MODE_FT4 = 1` |
| `Row[] decode(float[] audio, int sampleRate, boolean deep)` | 解码一个时隙 |
| `Row[] decode(float[] audio, int sampleRate)` | 普通解码 |
| `static Row[] decodeOnce(float[] audio, int sampleRate, boolean deep)` | 内部 open/decode/close |
| `void close()` | 释放 session |
| `static int version()` | mfsk-ffi 版本号（uint32） |
| `static String modeName(int mode)` | 模式名 |

`Row` 字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `text` | `String` | 已解好的报文，例如 `CQ JA1ABC PM95` |
| `snr` | `float` | 2500 Hz 参考带宽下的 SNR（dB） |
| `dt` | `float` | 相对时隙起点的偏移（秒） |
| `freq` | `float` | 音频频率（Hz） |
| `mode` | `int` | 0=FT8，1=FT4 |
| `flags` | `int` | bit0=用到呼号哈希表 |

原生行格式（`wsjtx_jni.c`）：

```
text \t snr \t dt \t freq \t mode \t flags
```

## 5. 时序和音频格式

- 采样率：**12000 Hz**
- 位深：float，范围约 **-1.0 ~ 1.0**
- FT8 时隙：**15 秒 = 180000 个采样**
- 调用时机：录音结束后（FT8CN 的 `OnGetVoiceDataDone` 回调里）
- 解码必须在下一个时隙开始前完成；普通模式通常远小于 1 秒，
  深度模式在手机上可能更久，建议实测。

FT8CN 的 `voiceData` 已经是 12 kHz float，可直接传入，不需要再转 `short[]`。

---

## 6. 深度解码说明

`deep = true` 时：

- `depth = MFSK_DECODE_DEPTH_BP_ALL_OSD`
  （完整 LLR 阶梯 + BP + OSD 回退）
- `strictness = MFSK_STRICTNESS_DEEP`
  （比 WSJT-X 默认更宽松的接受门限）

mfsk-core 的 FT8/FT4 默认会自己做 SIC（连续干扰消除/减法），
所以**不需要** FT8CN 原来的 `ReBuildSignal.subtractSignal(...)` 和
`DecoderGetA91(...)` 循环。原来的 `a91List`、`runDecode(...)` 可以不再使用。


只开 `protocols` 会编译失败。`mobile` = protocols + legacy + jtty，
不启用 rayon/serde，适合 Android。

在 `C:\Users\<you>\.cargo\config.toml` 加国内镜像：


## 8. 常见问题

### `UnsatisfiedLinkError: dlopen failed ... libwsjtx_Android.so`

- `.so` 是否在 `app/libs/<abi>/`，而不是 `app/src/main/jniLibs/`；
- 设备 ABI 是否匹配；
- 是否把 x86_64 的 `.so` 装到了 arm 真机；
- 是否被 Gradle 的 `abiFilters` 过滤掉；
- Android 15 设备需要 16 KB 对齐（本产物已满足）。

### `UnsatisfiedLinkError: ... undefined symbol`

本库静态链接了 mfsk-ffi，正常只依赖：

```
liblog.so libm.so libdl.so libc.so
```

如果出现 `libc++_shared.so`，说明用了别的编译方式；本目录的产物不需要它。

### 解码结果为空

- `voiceData.length` 是否约 180000（15 秒 × 12000）；
- 是否在时隙结束后才调用；
- 音频是否被静音/增益过低；
- 先用 `deep = true` 对比，排除门限问题；
- `WsjtxDecoder.version()` 是否正常。

### `IllegalStateException: open mfsk decoder failed`

`mfsk_session_open` 失败。检查 ABI 和 `.so` 是否完整；
必要时在 JNI 里打印 `mfsk_last_error()`。

### 深度解码很慢 / 发热

深度模式会跑 OSD 回退和减法，手机 CPU 较弱时可能接近数秒。
可以只在用户打开“深度解码”开关时启用；普通模式保持 `deep = false`。

### 特殊消息显示不完整

`WsjtxDecoder` 返回的是**可读报文**。第 4 步的解析覆盖了 CQ、标准 QSO、
自由文本和常见非标准呼号；DXpedition、Field Day、RTTY RU、EU VHF 等
特殊 `i3` 类型会退化成普通文本显示。FT8CN 内部的 QSO 状态机如果需要
这些字段，后续可以扩展解析器，或给 mfsk-ffi 增加结构化字段输出。

## 10. 后续可扩展

当前 API 只暴露了“整槽解码”，没有传 AP hint（我的呼号、对方呼号、
网格、QSO 频率）。mfsk-core 本身支持 AP，可在后续版本增加：

```java
nativeDecode(handle, audio, sampleRate, deep,
             myCall, hisCall, hisGrid, freqHint);
```

另外可以按需增加：

- FT4 界面和 7.5 秒时序；
- `mfsk_session_keep_known` 的跨时隙已知信号复用；
- 解码结果里的 77-bit payload / A91，用于高级 QSO 逻辑；
- 频谱、瀑布图复用 FT8CN 现有实现，不需要动。
