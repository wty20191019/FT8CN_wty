# wsjtx 快速档梯度实验记录

目标：平均解码耗时 < 100 ms，召回率尽量大。
评分规则：`score = 召回率(%) / 平均解码时间(ms)`，只在平均耗时 < 100 ms 的配置里比较。

- 设备：vivo V2338A（骁龙 8 Gen 3）
- 测试集：60 个 wav，1298 条参考消息
- 对照：原快速解码 940/1298 = 72.4%
- 说明：每轮只改一个变量，跑完立即记录；命中数是确定值，重复跑不变，只有耗时抖动

## 决策变量

| 变量 | 取值 | 说明 |
| --- | --- | --- |
| 段数 | 1~8 | 每段独立 session + 线程 |
| profile | 2 / 3 / 5 | 2=关 OSD+单遍，3=单遍，5=sic_early |
| SIC 轮数 | 0 / 1 / 2 | 由 profile 5/7/6 控制 |
| OSD | 开 / 关 | profile 2 关闭，profile 3 开启 |

## 梯度判断

- 段数 4→5→6→7（profile3）：召回 +0.9 / +0.8 / +0.4 点，耗时 +5 / +15 / +13 ms，正梯度递减到拐点。
- profile 2→3（开 OSD）：召回约 +2.9 点，耗时约 +12~15 ms，是召回方向最陡的一档。
- 1 段整范围搜索：耗时 537 ms，说明耗时不是随段数单调下降，1 段要搜索全部候选，最慢。
- 2→3→4 段（profile2）：召回 64.1 → 66.2 → 67.7，耗时 45.5 → 46.1 → 50.2，3 段性价比最高。
- deep 门限（A9）：几乎无收益，说明瓶颈不在接收门限。
- profile 5（sic_early）：召回 +20 点，但耗时 10 倍，不可用。

## 不同目标下的最优

| 目标 | 配置 | 召回率 | 平均 | score |
| --- | --- | ---: | ---: | ---: |
| score 最大 | **3 段 + profile2** | 66.2% | 46~47 ms | **1.40~1.44** |
| 召回最大（<100 ms） | 7 段 + profile3 | 72.7% | 97 ms | 0.75 |
| 召回/耗时折中（<100 ms） | 6 段 + profile3 | 72.3% | 83~84 ms | 0.86 |
| 追超低耗时 | 2 段 + profile2 | 64.1% | 45~46 ms | 1.38~1.41 |

注意：score 只看“单位时间召回率”，会天然偏向低召回、低耗时的配置。3 段 + profile2 只有 66.2%，低于原快速解码 72.4%；若要求召回不低于原快速解码，则只有 6 段/7 段 + profile3 可选。

## 与原快速解码的评分对比

原快速解码在本机（vivo V2338A）实测两次：72.4% / 65.7 ms 和 62.7 ms，score 1.10~1.16（取平均 64.2 ms，score 1.13）。

| 配置 | 召回率 | 平均 | score | 相对原快速 |
| --- | ---: | ---: | ---: | ---: |
| 3 段 + profile2 | 66.2% | 46.7 ms | 1.42 | +26% |
| 2 段 + profile2 | 64.1% | 45.9 ms | 1.40 | +24% |
| 4 段 + profile2 | 67.7% | 50.0 ms | 1.35 | +20% |
| 5 段 + profile2 | 68.6% | 54.6 ms | 1.26 | +12% |
| 4 段 + profile3 | 70.6% | 61.8 ms | 1.14 | +1%（基本持平） |
| 5 段 + profile3 | 71.5% | 68.9 ms | 1.04 | -8% |
| 6 段 + profile3 | 72.3% | 83.8 ms | 0.86 | -24% |
| 原快速解码 | 72.4% | 64.2 ms | 1.13 | 基准 |

结论：**有配置能超过原快速解码的单位时间召回率，但都是靠降低召回换来的**；没有任何配置能同时做到“召回 ≥72.4% 且 score 超过原快速解码”。要在 72.4% 召回下赢过基准，平均耗时必须压到约 63 ms 以内，而当前 72.3% 的最快配置是 83 ms。
