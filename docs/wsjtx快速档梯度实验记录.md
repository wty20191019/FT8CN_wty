# wsjtx 快速档梯度实验记录

目标：解码平均耗时 < 100 ms，召回率尽量大。

- 设备：vivo V2338A（骁龙 8 Gen 3）
- 测试集：60 个 wav，1298 条参考消息
- 对照：原快速解码 940/1298 = 72.4%，avg 112 ms（同机历史值）
- 说明：每轮只改一个变量，跑完立即记录

## 决策变量

| 变量 | 取值 | 说明 |
| --- | --- | --- |
| 段数 | 2~8 | 每段独立 session + 线程 |
| profile | 2 / 3 / 5 | 2=关 OSD+单遍，3=单遍，5=sic_early |
| SIC 轮数 | 0 / 1 / 2 | 由 profile 5/7/6 控制 |
| OSD | 开 / 关 | profile 2 关闭，profile 3 开启 |

## 梯度判断

- 段数 4→5→6：召回 +0.9 / +0.8 点，耗时 +5 / +15 ms，仍有正梯度但递减。
- 段数 6→7：召回仅 +0.4 点，耗时 +13 ms，P95 从 107 升到 140，已到拐点。
- profile 2→3（开 OSD）：召回约 +2.9 点，耗时约 +12~15 ms，梯度最陡且距离 100 ms 仍有空间。
- deep 门限（A9）：几乎无收益，说明当前瓶颈不在接收门限。
- profile 5（sic_early）：召回 +20 点，但耗时 10 倍，不可用。

## 结论

在“平均耗时 < 100 ms”的约束下，召回率已到平台：

| 配置 | 召回率 | 平均 | P95 | 评价 |
| --- | ---: | ---: | ---: | --- |
| 6 段 + profile3 | 72.3% | 83~84 ms | 107~111 ms | **推荐**，平均达标且尾部可控 |
| 7 段 + profile3 | 72.7% | 97 ms | 140 ms | 召回最高，但平均贴着上限、尾部差 |
| 6 段 + profile2 | 69.4% | 70 ms | 96 ms | 追速度时用 |

对照原快速解码（72.4% / 112 ms），6 段 + profile3 在召回基本相同的情况下把平均耗时压到约 84 ms。
